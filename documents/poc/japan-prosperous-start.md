## 3. 地図に置いたもの

生成は `tools/japan_map_scale/prosper_start.py`。`generate.py` が史実開始の地図を書いた直後に `apply()` を呼ぶ。規則（人口・区域の種類・守備隊・予備隊の数・初期金）は `prosperity.py` の `city_plan()`・`faction_reserves()`・`starting_gold()`。

### 3.1 都市

1. **人口**：本拠は階層で A6・B5・C4・D3（京都は +2 で6、本願寺は +1）。支城は重要度で −1（主要城）／−2。下限2、上限は「その都市の所有陸タイル − 1 − 山岳」。20km 地図はタイルが少ないため、六角（観音寺 5→3 など）と今川で 15km より小さい。
2. **建物**：本拠と主要城（重要度2）に土塁 `BUILDING_WALLS`（桑実寺は臨時政庁なので置かない）。人口4以上に穀倉。区域には基本の建物を1つ（市場・灯台・兵舎・祠・工房・図書館）、信仰3の本拠の聖地には寺院も。
3. **区域**：人口3以上で1つ、6以上で2つ（人口＋区域が所有陸タイル−1−山岳を超えない）。支城は主要城だけ1つまで。京都は2つ固定（9a）。種類は家の特色の高い順で、置けなければ次の特色の区域にする。
   - 置き場所：その都市の所有タイルで中心から3以内、山岳・資源なし。野営地は都市中心に隣接させない（`Districts.xml:46` NoAdjacentCity）。港は陸に接する海岸タイル（`:47` Coast・AdjacentToLand）で、そのタイルを都市の所有に加える（公式 Vikings の港4つはすべて所有タイル）。
4. **タイル改善**：働く市民の数（人口 − 区域数）だけ、中心から3以内に置く。資源のタイル（米＝農地、鉄・塩＝鉱山）→ 平地の農地 → 丘の鉱山の順。戦国ツリーで作れる農地・鉱山・石切場だけ（`poc/JAC_PoC_SengokuTrees/Data/JAC_Sengoku_Unlocks.sql:80-82`）。馬・絹・茶の資源タイルは牧場・農園が作れないので空ける。丘の農地は `CIVIC_CIVIL_ENGINEERING` が要る（`Improvements.xml:103-104`）ので置かない。
5. **森・湿地は消さない**（E1=b）：区域・改善は森・湿地のないタイルにだけ置き、足りなければ置く数を減らす（区域は次の特色の区域を試し、それも置けなければ諦める）。開拓者版と史実版の地図の `PlotFeatures` は同一（テストで確認）。置けなかった区域は 20km の松平・足利将軍家の各1つで、京都の聖地もその一つ（15km は 0）。

### 3.2 部隊と金

1. **守備隊**：全56都市の中心に1体。本拠と主要城は槍兵、支城は戦士。
2. **予備隊**：本拠の2体目（階層 A・B の弓兵）と、`round(√直轄石高中 ÷ 1.5)` 体（最低1）。本拠→主要城の順に、自勢力の陸タイル（山岳・都市中心以外、陸の区域は可）の中心から2以内、足りなければ3以内、それでも足りなければ自勢力の任意の陸タイル（本願寺の加賀、琉球の離島）。1タイル1体（公式 Vikings・Alexander と同じ。調査 §5.4）。公式 Vikings でも区域の上に部隊が19体いる。
3. **初期金**：`max(100, 10 × 直轄石高中 + 40 × 商業の特色)`（10単位で丸め）、足利将軍家は京都の商業で +100。地図の `PlayerAttributes(ID, 'Treasury', 'Balance', '…')` に書く。公式の前例は `DLC/NubiaScenario/Maps/NubiaScenario.Civ6Map`（100・50）と `DLC/WarMachineScenario/Maps/WarMachineMap.Civ6Map`（900）。2026-09-29 の実機で、人間の席の大内は地図の値（820）以上で始まった。開始時代の金 `StartEras` ERA_ANCIENT Gold=10（`Base/Assets/Gameplay/Data/Eras.xml:26`）が上乗せされるかは未確認のため、シナリオは「地図の値以上」で判定する。
4. 使った部隊は戦士・槍兵・弓兵だけ（研究なしで訓練できる。`JAC_Sengoku_Unlocks.sql:7-8`）。
5. **初期ユニットの表は空にする**：史実開始の2種では `MajorStartingUnits` を全行削除する（`Data/JAC_Japan_NoSettlers.xml`、公式の固定地図シナリオと同じ `<Delete/>`。例 `DLC/WarMachineScenario/Data/WarMachineScenario_RemoveData.xml:344-346`、`DLC/Indonesia_KhmerScenario/Data/Indonesia_KhmerScenario_RemoveData.xml:1492-1494`）。公式の表には開拓者のほか戦士（`Base/Assets/Gameplay/Data/Eras.xml:42`）と、難易度が王子より上の AI だけの戦士・労働者（`:44-45`）がある。部隊はすべて地図の `Units` の行から来る。

## 4. テスト

`python -m unittest discover -s tools/japan_map_scale/tests`（`tests/test_prosper_start.py`）：

1. 階層ごとの合計（勢力数・人口・部隊・区域・壁・改善・金）が上の表と一致し、本拠人口・1家あたりの部隊・金が A > B ≧ C > D。
2. 全都市の中心にその家の守備隊がちょうど1体（本拠・主要城は槍兵、支城は戦士）。
3. 部隊が海・山岳・通行不可・他家のタイルにいない。1タイル1体（軍事部隊が同じタイルに2体いない）。
4. 区域・建物・改善が §3.1 の規則どおり（所有・距離・野営地の隣接禁止・港は海岸・資源なし・戦国ツリーで残る建物と改善だけ・区域の建物は対応する区域の上）。
5. 京都の人口6と寺社・商業（20km は商業のみ）、各家の初期金。
6. 開拓者版の地図に部隊・改善・金・建物がない。
7. **決定性**：地図の写しに `apply()` を2回かけても、中身が収録済みの地図と同じ。`generate.py` を2回実行しても地図・manifest・シナリオのハッシュが同じ（手元で確認）。
8. 実機シナリオが最新で、ドライバの検証を通る。開始時の確認が読み込み時の記録を読む。開始時の確認に埋め込んだ家ごとの建物の種類別の数が、収録済みの地図の `Buildings` と一致する。最後の手順が、滅亡か本拠の喪失で失敗する。
9. 読み込み時の記録のスクリプトが史実開始の2種だけで動く（modinfo の条件）。`test_generate.py` で初期ユニットの表の全削除も確かめる。

## 5. 実機確認（メインセッションで実行）

シナリオ `tools/civ6-autotest/scenarios/japan-prosperous-15km.json`（検証：`python tools/civ6-autotest/scenario.py tools/civ6-autotest/scenarios/japan-prosperous-15km.json --check`）。

1. 開始直後（手順4）：全22家の都市数・人口・軍事部隊数・区域数・壁の数・改善数・種類別の建物数（宮殿・土塁・穀倉・区域の建物すべて）が地図どおりか、全都市の中心に自家の軍事部隊がちょうど1体いるか、軍事部隊が2体いるタイルがないか、金が地図の値以上かを確かめ、違えば止まる。戻り値は `家 都市/人口/部隊/区域/壁/改善/金` の並び。
   - 値はその時点の盤面ではなく、ゲームプレイスクリプト `poc/JAC_PoC_JapanMapScale/Scripts/JAC_Japan_StartState.lua` が読み込み時（1ターン目の処理の前、新規ゲームのときだけ）に Game プロパティ `JAC_JAPAN_START_STATE`（建物は `JAC_JAPAN_START_BUILDINGS`）へ書いた記録を読む。AI は UI 側の確認より先に1ターン目を動かすため（§5.1）。記録がなければ `no start state recorded`／`no start buildings recorded` で止まる。
2. その後 AI 自動進行 50 ターン（10ターンごとの集計：都市・人口・部隊・金・収支、滅亡は `DEAD`）。
3. 最後に `SURVIVORS T51 n/22: …（都市数、本拠を失った家は NO_CAPITAL） | DEAD: …` を返す。22家すべてが生き残り、全家が本拠を持つことを合格の条件とし、1家でも滅ぶか本拠を失えば `regression: SURVIVORS …` で失敗する。
4. 人間の席は大内（最大の家）。`allow_human_elimination` は main のドライバにないため使っていない（`feat/driver` にはある）。

判定：上の3で合否を決める。参考として、変更前の地図では、織田が4回中3回、50ターン以内に滅んだ（メインセッションの記録）。このシナリオで織田を含む滅亡の数と時期を比べる。1回の実行は乱数に左右されるので、数回まわして比べたい。

### 5.1 2026-09-29 の実機（`japan-prosperous-15km.json`、15 km）

開始直後の確認が止まった：伊達・北条・山内上杉の部隊が1体多く金が少ない（伊達 76／地図 310、北条 277／510、山内上杉 305／540）、武田・伊達・北条・山内上杉・今川・松平・朝倉・足利将軍家に守備隊のいない都市（足利5）。

原因は地図ではなく、確認より先に AI が1ターン目を動かしたこと。根拠：

1. 人間の席の大内は全項目が地図どおり（部隊10、金820以上、全都市に守備隊）。ずれは AI の家だけ。
2. 伊達の増えた1体は弓兵（弓兵3＝地図2＋1、槍兵・戦士は地図と同数）。既定の初期ユニットなら戦士（`Eras.xml:42`）で、弓兵にはならない。
3. 3家の金の減り方は 233.5・233・235 でそろう。弓兵（生産力60、`Base/Assets/Gameplay/Data/Units.xml:779`）の標準速度での購入額240から1ターン分の収入を引いた値に合う（購入額の式は `GlobalParameters.xml:334,465` の GOLD_PURCHASE_MULTIPLIER・PURCHASE_DIVISOR。240 は標準速度で広く知られた購入額で、この環境の画面と式では未確認）。
4. 伊達の守備隊・予備隊は、地図の位置からちょうど1タイル動いた位置にいた（戦士 (150,39)→(151,38)、(150,43)→(150,42) など6体）。地図の `Units` は全都市の中心に1体、1タイル1体（§4 の2・3）。

対応：確認を読み込み時の記録に切り替え（§5 の1）、初期ユニットの表を全削除（§3.2 の5）。地図の行は変えていない（`prosper_start.py` を再実行しても中身は同一）。初期金は地図の `Treasury` がそのまま効いているため、Lua で金を設定し直す処理は入れていない。

## 6. 入れていないもの

1. **備蓄（戦略資源の蓄え）**：入れない（E3=a）。公式の地図に `PlayerAttributes` で戦略資源を持たせる前例もない（公式地図の `PlayerAttributes` は Era・Tech・Civic・Treasury だけ）。
2. **追加の資源**：資源は資源調査の配置のまま。石高の差は金・部隊・改善で表した。
3. **漁船**：海のタイルは誰の所有でもないため置いていない。
4. **大名間の開戦の遅延**（`DIPLOMACY_EARLIEST_MAJOR_DOW_TURN`、調査 §7）：未実装。滅亡が減らなければ次の手として試す。
5. 城 `BUILDING_CASTLE`：戦国ツリーで石垣（T21）以降の建物なので置かない（調査 §5.1）。

## 7. 再生成

```
python tools/japan_map_scale/generate.py        # 地図4種・manifest・設定・シナリオ（本機能も含む）
python tools/japan_map_scale/prosperity.py      # 調査 JSON（地図を読む）

```

`generate.py` は Natural Earth・ETOPO の取得物を `tools/japan_map_scale/cache/` に置く（ハッシュ固定、Git 管理外）。

## 縮尺について

2026-09-29 のオーナー判断（SSOT 3.4）で、日本列島全体の地図は 15 km に決まった。15 km では 9a（京都に商業地区と聖地）を満たす。20 km 版は比較用として残し、京都は区域を置ける空きタイルが1つしかないため聖地を置かない（森は切らない：E1b）。

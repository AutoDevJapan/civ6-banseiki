# PR86の汎用本体総督枠を判定する短い診断

汎用の本体総督枠を1種追加し、未加入時のAI任命と、未配置時に取得証跡を読めるかを判定する診断を用意した。実機ではまだ実行していない。人物化の完成版ではなく、正本16.1が許可した同等代替の可否を調べる成果である。

正本9.4・4.7は公式称号の会計、公式の都市配置、一都市一人、定着後の都市効果を要求する。純Gameplayの人物状態では公式スパイ中和の対象となる本体総督がない、という先行調査を受けた。人物と枠の対応、および中和との接続は、この診断の後に親担当が実装する。

## 追加したものと費用

テスト専用MOD `poc/JAC_Test_NativeSlots` を別途有効にした場合だけ、万世紀の15km史実地図に追加する。既存の人物化MODのSQL・共有処理・会計UI・Gameplayは変更していない。

| 追加物 | 検証すること |
|---|---|
| `Data/JAC_NativeSlots_Probe.sql` | 人物に対応しない配置可能な本体総督1種。忠誠圧力8、遷移強度100、公式の基準定着5ターンを保つ |
| `Scripts/JAC_NativeSlots_GameCore.lua` | 実際のPlayer/Cityプロパティと公式獲得数・使用済み数をGameCoreから読む。証跡を書き込まない |
| `UI/JAC_NativeSlots_View.lua` | 公式の任命・配置操作、21AIの早期断言、観測値の記録、定着と保存復元の比較 |
| `leader-persona-native-slots-15km.json` | 主診断35手順。最初のAI手番と未配置時の証跡で早く失敗させる |
| `leader-persona-native-slots-activation-15km.json` | 発効時点の観測24手順。最後に元の未配置時の証跡を再判定し、後から発効しても合格にしない |

基礎昇進には公式のPlayerプロパティ用modifierとCityプロパティ用modifierを1個ずつ付けた。両方とも量は1。人物名、人物の固有技能、収量効果、任命資格を変える特性、常設の人物との対応は付けていない。通常の忠誠圧力自体がAIに任命価値を与える可能性を、隠さず検査する。

人間には公式社会制度から称号2個、21AIには各3個を与える。人間が比較用の配置不能な支払い総督を任命して1個、その後で通常枠を任命して1個を使う。**通常枠の1個は追加検証の支出**であり、人物の進化費用に算入した完成版の会計ではない。支払いの予約・人物の除去・人物との対応は呼び出さない。

## 最短の実機判定順

親担当が専用MODを導入したうえで、主診断を実行する。この担当はゲームの起動、MODの導入、実機接続をしていない。

1. 4〜5番で22人物の本体候補とKind登録がないこと、加入済み人物がないこと、公式称号の正の予算を確認する。
2. **8番**で1実手番を終えた21AIを調べる。全AIが3個以上の使用可能な称号を保ち、未対応の通常枠・支払い総督への任命も称号支出もないことを断言する。失敗時はここで止まる。
3. 9〜14番で比較用の支払い総督と通常枠を各1回公式任命する。両者を未配置のまま保ち、GameCoreで取得証跡と使用済み数の増加2個を読む。
4. **15番**で両方のPlayer証跡が正確に1であることを断言する。未配置の通常枠で読めなければ、ここで失敗する。称号の使用済み数やUI側だけの値から成功にしない。
5. 16〜20番で未配置のまま保存・読込し、証跡、任命状態、会計が一致することを確認する。
6. 21〜29番で人間の首都へ公式配置する。配置直後と4ターン後は未定着で都市証跡がなく、5ターン後に本体が定着し、配置先の都市証跡だけが1になることを断言する。各時点で21AIの任命・支出も再検査する。
7. 30〜35番で定着後に保存・読込し、本体の配置、定着時間、活動不能期間、Player/City証跡、追加支出の総数が一致することを確認する。

通常枠の任命直後に証跡がなく、発効時点の根拠が必要なら、別の観測シナリオを実行する。このシナリオも8番のAI条件は同じである。任命直後、配置直後、定着後の値を記録し、24番で**元の未配置時の記録**に証跡がないことを失敗として残す。元の値を後の値に置き換えない。

主診断の15番の失敗では後の発効時点は「未観測」と記録する。観測シナリオでは、配置直後だけで証跡が現れれば `SLOT_RECEIPT_AFTER_ASSIGNMENT`、定着後で初めて現れれば `SLOT_RECEIPT_AFTER_ESTABLISHMENT`、定着後もなければ `SLOT_RECEIPT_STILL_MISSING` を失敗理由に付ける。元の証跡がなくても後の定着確認を通した場合、それを主診断の合格には扱わない。

`Lua.log`には次の接頭辞で観測値を残す。元のPlayer/City証跡をLuaから書き込む処理はない。保存する診断記録には別の接頭辞を使う。

| 接頭辞 | 残す事実 |
|---|---|
| `JAC_NATIVE_SLOTS_AI` | 21AIそれぞれの獲得数、使用済み数、枠・支払い総督の任命有無、枠の忠誠圧力 |
| `JAC_NATIVE_SLOTS_OBSERVE` | GameCoreのPlayer証跡、比較用証跡、会計、実ターンと本体総督の配置・定着・活動不能状態 |
| `JAC_NATIVE_SLOTS_CITY` | 所有者・都市IDとGameCoreの都市証跡 |
| `JAC_NATIVE_SLOTS_LOYALTY` | 公式UIと同じAPIで読んだ、配置先都市の忠誠内訳。表示する量からAIの選択理由は断定しない |
| `JAC_NATIVE_SLOTS_FAIL` | 不合格条件。後から発効する証跡を任命直後の証跡に読み替えない |

## 公式資料との対応

以下の相対パスはSteam版Civ6のインストール先を基点とする。資料は読むだけで、公式ファイルは変更していない。

| 根拠 | 確認した事実と限界 |
|---|---|
| `Base/Assets/Gameplay/Data/Schema/01_GameplaySchema.sql:1143` | `DynamicModifiers`は種類・Collection・Effectを公式Typesへ参照する。存在する行とFKを検査する |
| `Base/Assets/Gameplay/Data/Modifiers.xml:2285,2690` | City/Playerの両Property modifierは `COLLECTION_OWNER`。効果はそれぞれCity/PlayerのProperty調整。**通常総督が未配置で発効することは、この登録だけでは分からない** |
| `DLC/Expansion1/Data/Expansion1_Schema.sql:131,177,190` | Governors、基礎昇進とのmodifier対応、GovernorPromotionSetsの公式構造 |
| `DLC/Expansion2/Data/Expansion2_Schema.sql:337,360,389,402` | GS側の同構造と配置不能を指定する表。追加した通常枠には配置不能の行を付けない |
| `DLC/Expansion2/Data/Expansion1_Governors.xml:69–75` | 通常総督の忠誠圧力8。遷移強度100の通常例を採用する。特殊な防衛総督の150は採用しない |
| `DLC/Expansion1/Data/Expansion1_GlobalParameters.xml:70`、`DLC/Expansion2/Data/Expansion1_GlobalParameters.xml:65` | 基準定着時間は5ターン。データの値と実際の総督の時計を別々に確認する |
| `DLC/Ethiopia/Data/Ethiopia_SecretSocieties_MODE.xml:124,198,714` | 配置不能な秘密結社総督の昇進が国単位の効果を持つ公式例。配置可能な通常総督の任命直後の証跡を証明する例ではない |
| `DLC/Expansion2/UI/Additions/GovernorPanel.lua:548` | 公式任命は `UI.RequestPlayerOperation` と `APPOINT_GOVERNOR`。種類のIndexを渡す |
| `DLC/Expansion2/UI/Additions/GovernorAssignmentChooser.lua:397` | 公式配置では総督種類・都市所有者・都市IDを渡す |
| `DLC/Expansion1/UI/Additions/GovernorSupport.lua:12–28`、Expansion2の同ファイル | 本体の配置都市、定着状態、定着所要時間、経過時間、活動不能の残存期間の読取り |
| `DLC/Expansion2/UI/Additions/CityPanelCulture.lua:132` | 都市の忠誠内訳を読む実在API |
| `Debug/Player.ltp:651,673,901` | 公式称号の獲得数・使用済み数の読取り、公式社会制度の進捗を与える診断操作 |
| `Debug/City.ltp:805` | 都市に保存されたPropertiesを表示する公式診断。取得証跡自体の発効は実機で判定する |

GameCoreの読取りとUIから呼ぶ橋は、既存の人物化・支払い候補と同じPlayer/City Property経路を使う。都市への任命・配置・定着をGameCoreから未確認のsetterで強制する処理は追加していない。動的特性と任命資格の調査はやり直していない。

## 実行済みの検査と未確定点

- 公式のBaseとGSデータを、既存の監査ローダーでメモリ上に再構築した。GS同梱のExpansion1データ、戦国SQL、人物化SQL、支払い候補SQL、追加枠SQLを実行した。FKを有効にしたまま、既存の公式データ読込み不足に由来する違反との差分が0であることを確認した。これは全DLCを含む実機のDatabase.log検査の代用ではない。
- 新規16検査と、既存の支払い・会計画面・Luaファイル名の回帰を合わせた**36検査が成功**した。実在するSchemaでの参照、22人物の除去と実偉人の維持、元の支払い候補の不変、証跡欠落・AI無断任命・称号ゼロ・AI数不足の拒否を確認した。
- 新規Lua2ファイルと、両シナリオのLua断片41個が構文検査に成功した。シナリオの `--check` は主35手順・観測24手順とも成功した。実機へは接続していない。
- 元の113手順 `leader-persona-15km.json` と人物化MODには、起点からの差分がない。
- **未確定**: 正の称号を持つ21AIが無断任命しないこと、通常総督のPlayer証跡の任命直後の発効、都市証跡と5ターン定着の一致、実際の保存復元。モックの成功からこれらを合格にしない。
- **親の残範囲**: 人物と枠の一対一対応、枠任命を含めて二重に費用を使わない完成した会計、配置解除・再配置、公式スパイの中和と回復の完整実装。

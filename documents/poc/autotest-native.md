# Civ6検証ドライバーのRust移植

PR87の検証ではPythonを新たに実行せず、`tools/civ6-autotest-native/` のRust製モジュールを使う。2026-10-02、オーナーが既存Pythonの例外を認めず、移植後に実機検証を続ける方針を選んだ。

## 対応する検証

対象は日本吸収127手順、英雄再召喚101手順、宣教師診断13手順である。既存JSONのLua命令と検査条件を読み込む。RustからFireTunerの公式接続へ命令を送り、ゲーム内Luaで検査する。Pythonのソースは移植時の参照資料であり、実行・import・機能追加を行わない。

対応する操作は再起動、MOD切替、設定、開始、Lua、待機、保存、メニューへの終了、読込、手番終了、自動進行、待機時間の指定である。未対応のスクリーンショットや性能計測などが指定された場合は、実行前に失敗する。省略して成功とは扱わない。

- 起動はSteamのDX11指定を使い、複数プロセスを拒否する。入力前に対象ウィンドウと前面を照合する。
- MODのGUID・重複・導入、更新時刻、DDSとBLPに含まれるアトラス名を検査する。
- Lua命令の応答が不明な場合は、その命令を再送しない。開始・読込による接続切替では、同じ命令を送り直さず画面遷移を観測する。
- 保存名を実行フォルダごとに分け、既存の保存を上書きしない。保存完了のイベントと非空の実ファイルを照合する。
- 元のLuaの取得値を保存し、読込後の値との完全一致を検査する。
- 検証モードの早送りは時代境界を通常処理し、省略数を記録する。連続性能の測定とは扱わない。
- ログは保存世代・位置・ハッシュで範囲を管理する。必須ログの欠損、空の証拠、JACのエラー・実行時エラー・テクスチャ欠損を合格にしない。

## 標準の実機ツールとの接続

ゲーム資源の保持、待機列、30分の譲渡は引き続き `D:/CC/Tools/civ6-live/live_chain.exe` が担当する。独自の共有ロックや待機処理は作らない。

標準ツールの実行元プロセスに限り、`CC_LIVE_PYTHON` にRust製の実行ファイルを指定する。この環境変数名は既存ツールの契約であり、指定先はRust製の実行ファイルである。標準ツールが渡す `scenario.py` と `tuner.py` の位置引数は入口の識別にだけ使い、Pythonを起動しない。機械全体の環境変数や標準ツールを変更しない。

標準ツールが再起動を加える場合も、元の127・101・13手順を全て照合する。結果は `result.json`、`steps.jsonl`、通信出力、ゲームの3ログへ保存する。結果の保存に失敗した検証を合格にしない。

## 検査と現状

初稿47件の後、統合版のRust単体検査50件が成功し、省略0件だった。静的解析は警告0件、実機用のreleaseビルドと、3シナリオ127・101・13手順の全Lua片の構文検査が成功した。これはCiv6実機の合格ではない。別モデルレビューとRust版による実機3本は未完了である。

通常691件・旧ドライバー252件・吸収Lua120件は以前のPython実行系で得られた前担当の実測で、今回Rustで同件数を再実行したとは主張しない。Civ6実機34の114手順の成功と次時代の未達は、[再開記録](../worklogs/pr87-recovery-20261002.md)に残す。

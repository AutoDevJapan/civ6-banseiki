# リポジトリルール

このリポジトリで作業する人・コーディングエージェントが必ず守るルール。オーナーの指示で恒久的に決まったものを記録する。ルールを変えるときはこのファイルを更新する。

## ドキュメント

1. 仕様の正本（SSOT）は `documents/spec/ssot/` で、章・節ごとのファイルに分割している。本文中の「本書」はこのディレクトリ全体を指す。入口は索引 `documents/README.md`
2. 仕様を変えるときは SSOT の該当ファイルを更新する。仕様を別のファイルに書かない
3. 変更の経緯は Git の履歴で管理する。SSOT に更新履歴の章を作らない
4. 新しいドキュメントは `documents/` 配下に置き、`documents/README.md` の索引に追加する
5. 使っていない目印コメント（生成スクリプト用のマーカーなど）を残さない
6. SSOT は大きいので、全体を一度に読み込まず、必要な節のファイルだけを読む

## 判断と矛盾の扱い

1. オーナーの判断が必要な事項は `documents/questions.md` に書く。決まったら SSOT の該当節へ反映し、質問リストからは削除する
2. SSOT 内の矛盾は、エージェントが独断で解消しない。オーナーに対話形式で質問し、オーナーの指示で解消する
3. オーナーが「別途議論する」とした事項は、`documents/questions.md` の「議論待ち」に背景と論点をまとめ、勝手に決めない
4. 未決事項をどの順番で議論するかはエージェントが決め、オーナーに対話形式で質問してよい。実装の着手に必要なものから優先する

## Git と PR

1. オーナーが「コミットして」と言ったら、コミットに加えて push し、PR を作成する（既存の PR があれば更新する）ところまで行う
2. `main` に直接コミットしない。作業ブランチを切って PR を作る（空のリポジトリへの最初のコミットだけは例外）
3. PR を作ったらセルフレビューを行い、指摘は PR にコメントとして投稿する。指摘を修正し、指摘が出なくなるまで繰り返したら、オーナーの確認なしでマージしてよい

# 判断が必要な事項（質問リスト）

実装を進めるにあたり、オーナーの判断が必要な事項。根拠は [準備度調査](research/civ6-modding-readiness.md) を参照。回答が決まったら SSOT の該当節へ反映し、この表からは削除する。

- 優先度：**PoC前に必須** ＞ **MVP前に必須** ＞ **後回し可**
- 「推奨」は判断が無い場合に採用する既定案

| # | 質問 | 選択肢 | 関連節 |

| Q57 | 停戦裁定の費用・拒否の不利益に使う「正当性」の定義。SSOT 3.2 は費用と不利益に正当性を使うと決めたが、9.4 の正当性（旧9状態案）は未採用で数値が無い（15.2）。今は勢力ごとの数値（初期50、請求で -5、拒否で -15）を記録するだけで、効果は無い（[実装メモ](poc/court-arbitration.md)） | ① 今の数値の置き場のまま使い、正当性を 9.4 で定義したら効果をつなぐ（推奨） ② 外交的支持（Favor）で代える（費用が Favor と金だけになる） ③ 各都市の忠誠度（Loyalty）で代える | 3.2、9.4 |
| Q58 | 裁定を拒んだ勢力への「討伐の大義（開戦理由）」の中身。Civ6 の Lua と修正値には、特定の相手への開戦事由・不満（Grievance）を足す手段が無い。今は大義が立つ期間（10ターン）を記録し、全勢力に通知するだけ | ① 記録と通知のまま、討伐の勅命（設計案で後回し）を入れるときに効果を決める（推奨） ② 大義のある相手への宣戦で、戦争屋の不利益を免除する方法を調べて付ける（公式に使用例が無い） ③ 大義のある相手と戦う勢力に Favor・金を与える | 3.2 |
| Q60 | 1573年以降の足利将軍家の裁定。SSOT 3.2 は「勢力は残り、裁定の力だけを失う」、設計案は「等倍（朝廷直接の裁定と同じ）に戻る」。今は SSOT に合わせ、他家どうしの停戦の発議をできなくし、当事者としての請求は他家と同じく等倍で残した | ① 今のまま（推奨。SSOT の文言どおり） ② 他家どうしの発議も等倍で続けられるようにする（設計案の読み） | 3.2 |
| Q61 | 天下統一で城を合算する「最初から組んでいる同盟」の範囲（[合算の PoC](poc/unification-pact.md)）。勝利の要件はチーム単位なので、ゲーム設定のチームは追加の実装なしで合算される | ① ゲーム設定のチームだけ（推奨。実装済み） ② 1534年の開始時の同盟（味方8組）も合算する（30ターンの期限で終わり、結び直さない同盟なので、終わったときの扱いも決める） | 3.1 |
| Q62 | チームでの勝者。SSOT 3.1 は「主体となる勢力だけが勝利する」だが、Civ6 の勝者はチーム単位（`Game.GetWinningTeam`）で、チームの一部だけを勝たせる仕組みがない。今はチーム全員が勝つ | ① チーム全員の勝利とする（推奨。エンジンどおり） ② 主体以外の勝利画面を敗北表示に差し替える（UI の上書き。チームの主体の決め方も決める） | 3.1 |
| Q63 | 天下統一同盟の主体・参加・解消。今は、申し込んだ家が主体、人間の家は受諾で加わる、AI の家は申し込んだ家と同盟中なら即加わる、AI からは申し込まない、1家は1同盟、勝利まで抜けられない、主体が滅亡したら数える城の最も多い参加者（同数なら小さい ID）が継ぎ、参加者が残らなければ消える、登録城のない地図では組めない | ① 今のまま（推奨） ② 抜けること（または相手との交戦で解けること）を認める ③ AI からも申し込む（AI の判断基準を決める） | 3.1 |
| Q64 | 開拓者から始める版（登録城なし）での天下統一同盟。SSOT は「城を合算」なので、今は合算せず、チームごとの本拠の条件で判定する | ① 合算しない（推奨） ② 同盟で全勢力の本拠（最初の首都）を合算する | 3.1 |
